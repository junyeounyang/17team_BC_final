## 2. 준비

- **SUMO 1.27.1** 과 `SUMO_HOME` 환경변수. 설치는 수업 저장소의 `project_materials` 안내를 따른다.

- **Python 3.12** (만든 PC 기준), 패키지: `torch`, `numpy`, `gymnasium`, `tensorboard`(train_bc.py 에 필요),
  `matplotlib`(도로 파일을 다시 만들 때 필요). `traci`·`sumolib` 은 SUMO 의 `tools` 에서 불러온다.
- 폴더는 어디에 풀어도 된다. 명령은 **이 폴더에서** 실행한다 (데이터·모델 경로가 이 폴더 기준).
- 첫 실행 때 `[daehakro_env] 대학로 도로를 사용합니다: ... (만들어 둔 파일 그대로)` 가 나오면 정상이다.
  `(새로 만듦)` 이 나오면 파일 수정 시각이 바뀌어 도로 파일을 다시 만든 것이다. SUMO 1.27.1 이면 똑같이 만들어지지만,
  다른 버전이면 도로가 달라질 수 있다. (압축을 풀 때 수정 시각을 유지하면 다시 만들지 않는다.)

## 6. PPO 담당자 유의사항 (중요)

### 6-1. 환경을 바꾸면 BC 와 비교할 수 없다

- `env\` 는 BC 학습·평가에 쓴 환경에 **긴급차 보조 수정 1건**이 더해진 상태다 (2026-11-19, `daehakro_emergency.py` 의 `_blocked_ahead`).
  - 고친 버그: 로터리 북동 교차로(J_NE) 안에서 소방차와 버스가 서로를 기다리며 멈춤 → 정체가 AV 까지 이어짐.
  - `logs_600` 의 BC 결과는 **수정 전** 환경에서 나왔다. 수정이 영향을 준 것은 1,500회 중 2회(오래 멈춤 2건)이고,
    수정본으로 그 두 장면을 다시 돌리면 정상 도착한다. 수정 후 AV 없이 20시간 돌린 시험: 텔레포트 0, 긴급차 관련 충돌 0.
- 관측 48개·행동 2개 정의(`env\daehakro_env.py`, `env\mdp_config.py`)를 바꾸면 BC 모델을 쓸 수 없다.
- 도로를 만드는 코드(`daehakro_builder.py`, `daehakro_config.py`, `daehakro_deco.py`)를 고치면 다음 실행 때 도로 파일을 자동으로 다시 만든다.
  다른 프로그램이 돌고 있지 않을 때 고칠 것.
- AV 는 **정책의 행동으로만** 움직인다. SUMO 의 자동 판단을 끄고(speed mode 0, lane change mode 0), 차로변경은 안전 검사
  (`mdp_config.py` 의 `lane_change_safety`)를 통과할 때만 실행한다. 긴급차 보조는 AV 를 절대 움직이지 않는다 (`skip=(AV id,)`).

### 6-2. BC 모델을 PPO 에 옮길 때 — 변환 코드가 필요하다

지금 `train.py` 는 PPO 를 무작위 가중치로 시작하고, `model.pt` 를 불러오는 기능이 없다. 게다가 두 신경망의 모양이 다르다.

| | BC (`model.pt`) | PPO (`train.py` 설정: `policy_type="hybrid"`) |
|---|---|---|
| 입력 정규화 | 있음 (`obs_mean`, `obs_std` 가 파일 안에 있음) | 없음 |
| 은닉층 | 256-256 ReLU | 256-256 ReLU (**같음**) |
| 가감속 출력 | 선형값 (환경이 [-1, 1] 로 자름) | `tanh(mu)` + 탐험 폭 `log_std` |
| 차선 출력 | 연속값 1개 (환경: ≥ +0.5 왼쪽, ≤ −0.5 오른쪽) | 3갈래 선택 (왼쪽 +1 / 유지 0 / 오른쪽 −1) |
| 가치 출력 | 없음 | `v_head` (새로 학습해야 함) |

옮기는 방법 (numpy 로 계산이 맞는지 확인함):

1. **정규화를 첫 층에 합친다**: `W1' = W1 / std` (입력 열마다 나눔), `b1' = b1 − W1 · (mean / std)` → `trunk.0`.
   BC 출력과 차이 1e-14 (사실상 같음).
2. 둘째 층(`fc2`)은 그대로 `trunk.2` 에 넣는다.
3. **가감속**: `fc3` 의 첫 행 → `mu_head`. 단 PPO(hybrid)는 tanh 를 씌워서 강한 명령이 약해진다
   (예: BC −1.37 → 환경에서는 −1.0 으로 꽉 제동, PPO 는 tanh 로 −0.88).
   시범 데이터 관측 2만 개로 재 보면 **12% 의 상황에서 0.1 이상 차이**가 났다. 똑같이 하려면 tanh 없는 정책으로 바꾸는 코드 수정이 필요하다
   (예: `GaussianActorCritic(squash_mean=False)` 를 쓰게 하거나 hybrid 의 tanh 제거).
4. **차선**: `fc3` 의 둘째 행 값을 y 라 하면 3갈래 점수를 `[k(y − 0.5), 0, k(−y − 0.5)]` 로 두면 된다 (`lane_head` 의 행 순서 = 왼쪽, 유지, 오른쪽).
   argmax 판단이 BC 와 **100% 같다** (k 는 클수록 결정적, 예: 10).
5. **가치(`v_head`)는 새로 학습**한다. 처음 몇 번의 업데이트는 정책을 고정하고 가치만 학습(예열)하는 것을 권한다.
   엉터리 가치로 계산한 advantage 가 BC 정책을 금방 망가뜨린다.
6. **탐험 폭**: `init_log_std = −0.5` (σ 0.61) 는 BC 운전을 크게 흔든다. −1.5 정도(σ 0.22)에서 시작하고, 학습률도 낮게(예: 3e-5 ~ 1e-4) 시작하는 것을 권한다.
7. 옮긴 뒤 `data\demo_600.npz` 의 관측으로 BC 출력과 PPO 결정적 출력(`det_action`)을 비교해 확인한다.
8. `test.py`(평가)는 `train.py` 의 `HPARAMS` 로 PPO 신경망을 만들어 불러온다. 신경망 설정은 `train.py` 한 곳에서만 바꿀 것 (아니면 평가 때 불러오기 실패).
9. (선택) PPO 손실에 BC 손실을 같이 걸면(`data\demo_600.npz` 사용) 초반에 정책이 무너지는 것을 막는 데 도움이 된다.

### 6-3. 보상

- 대학로 환경은 `env\daehakro_env.py` 의 `REWARD` 표(243행 부근)를 쓴다:
  진행 +0.1/스텝(제한속도로 달릴 때) · 시간 −0.01/스텝 · 앞차에 바짝 붙음 최대 −0.05/스텝 · 사이렌 차 앞을 막음 −0.1/스텝 ·
  도착 +10 · 차와 충돌 −20 · 보행자와 충돌 −40 · 신호위반 −15 · 횡단보도 −10 · 양보 위반 −8 · 오래 멈춤 −5 · 경로 이탈 −10.
- **`train.py` 의 `REWARD_OVERRIDES` 에 있는 키(`collision_penalty`, `arrival_bonus` 등)는 수업 고속도로용이라 대학로 보상에 영향이 없다.**
  바꾸려면 대학로 키 이름으로 적는다 (예: `red_light_penalty=20.0`).
- `env.penalty_scale` (충돌·위반 벌점 배율, 기본 1): 환경 설명에는 "train.py 가 학습 초반에 낮췄다가 올린다" 고 적혀 있지만
  **지금 `train.py` 에는 그 코드가 없다.** 이 배율은 처음부터 학습하는 PPO 가 '서 있기만 하기' 를 배우는 것을 막는 장치라, BC 에서 시작할 때는 1 그대로 두는 것이 자연스럽다.
- 실패 분석(5절)에서 본 개선 포인트:
  - 실패의 3/4 이 '앞차에 밀려 붙음'. 지금 바짝 붙음 감점(`tailgate_*`)은 서 있을 때 기준이 '최소 간격 + 1 m' 이고 최대 −0.05/스텝이라 약하다 → 강화 검토.
  - 양보 신호(관측 [40])를 무시하고 가속하는 습관, 횡단보도 위에 서는 습관.
  - **충돌 기준(2.5 m)은 바꾸지 말 것** — 바꾸면 BC 결과와 비교할 수 없다.

### 6-4. 평가 규칙 (BC 와 비교하려면 똑같이)

- 최종 평가: seed 110, 120, 130, 140, 150 각 300 에피소드 (`eval_daehakro.py --seed`). 중간: seed 100 × 100, 가벼운: seed 99 × 50.
- 평가는 결정적 행동(`predict(obs, deterministic=True)`)으로 한다.
- 같은 seed 면 같은 교통이 나온다 (seed 가 numpy 난수를 고정하고, SUMO 를 켤 때마다 SUMO seed 를 거기서 뽑음). 단 **같은 코드·같은 SUMO 버전**일 때만.
- 에피소드 규칙: SUMO 를 켜면 300초 동안 차를 채운 뒤 AV 를 넣는다. AV 가 240초 연속 서 있으면 '오래 멈춤' 으로 끝나고 다음 에피소드는 SUMO 를 새로 켠다.
  시뮬레이션 시각이 2600초를 넘어도 다음 에피소드에서 SUMO 를 새로 켠다.

### 6-5. 시간·설정

- `train.py` 기본 50만 스텝, 환경 1개 → 이 PC 속도(초당 약 17스텝)로 **8시간 이상** 걸린다 (중간 평가 포함 시 더).
- **`train.py` 의 `RUN_NAME = "ppo_scratch"` 를 바꿀 것.** 그대로면 결과가 `results\ppo_scratch` 에 저장된다 (원본 폴더에 같은 이름의 예전 실험이 있어 헷갈림).

### 6-6. 알려진 도로 약점 (드묾, AV 평가에 거의 영향 없음)

AV 없이 20시간 돌린 시험 기준:
- 로터리 북동쪽 진입로(`NE_in`): J_NE·J_NW 신호 연계 때문에 최대 약 220초 대기.
- M 교차로 옆길(N) 출구: 대학로 북쪽 방향이 꽉 막히면 끼어들기 어렵다 (20시간 중 1회 296초). AV 경로가 아니다.
- 차끼리 저속 충돌이 드물게 있다 (O 교차로, 이화장길 옆, A 교차로 앞 U턴 대기 차로). 긴급차와는 관계없다.
